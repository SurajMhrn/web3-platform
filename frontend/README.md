# Frontend — Web3 Platform

React 19 + Vite + TypeScript client for the Web3 Platform (Phase 1): registration/login,
wallet connect, on-chain identity, ERC20 token creation/transfer, transaction history,
notifications, dashboard, and an admin panel.

## Stack

- **React 19** + **Vite** + **TypeScript**
- **react-router-dom** for routing, **zustand** available for client state (not yet used
  outside React context)
- **react-hook-form** + **zod** for form validation
- **ethers v6** + **Reown AppKit** (`@reown/appkit`, `@reown/appkit-adapter-ethers`) for
  wallet connect (MetaMask, WalletConnect, etc.)
- **axios** via a single shared client (`src/services/apiClient.ts`)

## Getting started

```bash
npm install
cp .env.example .env   # fill in VITE_WALLET_CONNECT_PROJECT_ID — see below
npm run dev
```

The app throws on startup if `VITE_WALLET_CONNECT_PROJECT_ID` is missing — get a free
project ID at [cloud.reown.com](https://cloud.reown.com). `VITE_API_URL` should point at
the backend (defaults to `http://localhost:5000/api` if unset). See `.env.example` for
every variable.

The backend must be running (see `../backend/README.md`) and, for on-chain features, a
local Hardhat node with contracts deployed (see `../blockchain/README.md`).

## Auth

There is **no token in client-side JS** — `AuthContext` (`src/contexts/AuthContext.tsx`)
holds only the logged-in user's profile in React state. Authentication itself lives
entirely in httpOnly cookies set by the backend; every request goes through the shared
`apiClient` (`src/services/apiClient.ts`) with `withCredentials: true`, so the browser
attaches the cookies automatically. This closes off the main risk of keeping a JWT in
`localStorage`: an XSS bug can no longer read it out.

`apiClient`'s response interceptor transparently retries a request once via
`POST /auth/refresh` on a 401 before giving up — a session silently renews itself as long
as the refresh cookie (7-day lifetime) is still valid, without any page reload.

`ProtectedRoute`/`AdminRoute` (`src/components/ProtectedRoute.tsx`) gate routes on
`isAuthenticated`/`isAdmin` from `AuthContext` — this is a UX convenience only; the real
authorization check happens server-side on every request.

## Wallet-connect flow

1. `Web3Provider.tsx` initializes Reown AppKit with two networks: a local Hardhat node
   (chain 31337, where contracts are actually deployed during development) and Sepolia
   testnet.
2. Connecting a wallet is handled entirely by AppKit's `<appkit-button>` web component —
   no custom connect code needed.
3. **Linking** a connected wallet to the account (`DashboardPage.tsx`) proves ownership
   without a transaction: the backend issues a one-time nonce, the wallet signs a
   plain-text message containing it (never blind/typed-data signing — the user can read
   exactly what they're signing), and the backend recovers the signer address from the
   signature to confirm it matches.
4. **On-chain registration** and **token creation/transfer** are real transactions,
   sent directly from the connected wallet via `ethers` `Contract` calls
   (`src/services/web3Service.ts`, `TokenManagementPage.tsx`) — the wallet pays gas.
   The backend is only informed afterward, to keep a transaction/notification history.

Contract addresses and ABIs come from `src/constants/deployments.json`, which is
regenerated by the blockchain workspace's deploy script — never edited by hand.

## Testing

```bash
npm test
```

Vitest + React Testing Library, covering: `web3Service`'s pure helper functions,
`AuthContext`'s session bootstrap/logout, `ProtectedRoute`/`AdminRoute` redirect behavior,
form validation (login/register/setup-profile), `NotificationBell`'s polling and
mark-as-read flow, and `TokenManagementPage`'s deploy/transfer handlers (with `ethers`
mocked — no real wallet or chain involved).

**Not covered** by this suite, and out of scope for now: true wallet-popup end-to-end
flows (connecting a real MetaMask/WalletConnect wallet, signing a real transaction) —
those need a browser automation tool driving an actual wallet extension (e.g.
Playwright + a test wallet) rather than unit tests, and aren't set up yet.

## Project layout

```
src/
  contexts/     AuthContext — logged-in user state, backed entirely by cookies
  providers/    Web3Provider — Reown AppKit setup (networks, wallet connect)
  services/     apiClient (shared axios instance + 401-refresh interceptor), web3Service
                (contract helpers), and per-page on-chain calls
  components/   ProtectedRoute/AdminRoute, NotificationBell
  pages/        one file per route
  constants/    contract addresses/ABIs (generated) and typed accessors
```
